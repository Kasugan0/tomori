# 01-案例说明（`#141` 公共照明故障工单系统）

> **适用读者**：全员（产品、设计、后端、前端、测试、运维、审计）。

---

## 1. 背景与目标

### 1.1 业务背景

郑州市城市照明日常巡查中，「灭灯 / 灯具破损 / 灯头遮挡」三类高频故障依赖巡查员现场拍照上报，随后由运维管理员分级派工、维修员接单维修、巡查员验收闭环——流程长、时限严（郑州令第 152 号 48h 法定义务）、责任链需全程可审计。`#141` 系统为此构建**工单全生命周期管理 + 静态图片 AI 辅助识别**的单体应用。

### 1.2 系统目标

- **全流程闭环**：`报障 → 分级派工 → 维修 → 验收 → 关闭或返修`（含 `3` 轮返修上限，`rework_count <= max_rework_rounds` 默认 `2`）；
- **AI 辅助但不替代**：静态图片经 `yolo26s` `nc=3` 模型输出 `streetlight_on`/`streetlight_off`/`streetlight_damaged` 候选，**AI 产出必须经巡查员确认**方可建单（`requires_inspector_confirmation` 恒 `true`），夜间正常亮灯按 `D-30` 回传作参照框（`is_fault_candidate=false`）；
- **法定时限刚性**：`48h` `repair_deadline_at` 由 `business_rules['sla_policy']` 表驱动（`D-11` 郑州市令第 152 号第 19 条第 3 款），不可扩展为其他时限；
- **全域可审计**：所有 `ticket`/`dispatch`/`rework`/`notification` 状态变更经 `state_machine.transition_*()` 唯一入口 + `audit_logs` 同事务写入（`I7`）+ 通知 fan-out（`I8`）。

### 1.3 业务范围

| 域 | 内容 | 规模（实测） |
|---|---|---|
| **角色** | `ADMIN`（管理员） / `INSPECTOR`（巡查员） / `TECHNICIAN`（维修员） | `3` 个（`roles` 表） |
| **业务端点** | `auth`/`tickets`/`dispatches`/`master_data`/`operations`/`rework`/`business-rules`/`notifications` | `60` 个（`61` 含 `health`） |
| **数据表** | `fault_tickets`/`dispatch_records`/`rework_orders`/`acceptance_records`/`repair_processes`/`material_usages`/`fault_evidences`/`notification_tasks`/`audit_logs`/`accounts`/`roles`/`account_roles`/`scope_authorizations`/`maintenance_regions`/`lighting_points`/`facility_assets`/`business_rules` | `17` 张（`schema.sql`） |
| **状态机** | `A` 故障单 / `B` 派工 / `C` 返修 / `D` 通知任务 | `4` 套、`29` 态、`36` 转移规则条目（`(from,to)` 字面图边 `47`）、`11` 终态、`0` 死路 |
| **视觉推理** | `yolo26s` `nc=3` ONNX `[1,3,1280,1280]→[1,300,6]` + OpenCV 物理度量融合 | `streetlight_on`/`off`/`damaged` 三类；`streetlight_occluded` 按 `D-41` 弃用 |
| **测试覆盖** | 单测+集成 + E2E + testid + 变异杀灭 | `118` + `31` + `128` + `19`（`verify_testids` `128/128`，覆盖率 `69%`） |

### 1.4 非业务范围（`N1`–`N5` 硬红线）

- **N1** 不接实时监控（无 `RTSP`/流媒体/视频帧）；
- **N2** 不做远程灯控（无 `MQTT`/IoT/继电器/PLC 端点）；
- **N3** 不做能耗/电量预测（无 `timeseries`/预测库）；
- **N4`V1`** AI 候选必须人工确认方可派工（`confirmed_by_inspector` 三层强制）；
- **N5`V2`** 不替代现场电气安全检查（`replaces_electrical_safety_check` 恒 `false`）。

## 2. 术语

| 术语 | 定义 |
|---|---|
| `fault_type` | `LAMP_OUT`/`FIXTURE_DAMAGED`/`OCCLUDED`/`ELECTRIC_HAZARD`/`FLICKERING`/`OTHER`（`fault_tickets.fault_type` DB `CHECK` 枚举；`OCCLUDED` 已弃用于 `nc=3` 模型但保留 `API` 手工报障） |
| `priority`/`severity` | 工单优先级 `P1`–`P4` 由 `grading_rules` 表驱动确定性计算（`grading_score` 写 `NULL` 固化快照），`suggested_severity_hint` 为 AI 侧提示（`none`/`P2`/`P3`） |
| `scope`/`scope_authorizations` | 角色×区域的业务范围授权（`MANAGE`/`INSPECT`/`REPAIR` 三值），`deps.py` `FORBIDDEN_*` 越权守卫 |
| `Idempotency-Key` | `12` 个必需写端点的幂等键（`X-Idempotent-Replay: true` 重放响应；`pg_try_advisory_xact_lock` 咨询锁 + `audit_logs` append-only） |
| `state_machine` / `transition_*` | `src/backend/tomori/services/state_machine.py` 唯一状态变更入口（`transition_ticket`/`transition_dispatch`/`transition_rework`/`transition_notification`），同事务写 `audit_logs` 与 `notification_tasks` |
| `nc=3` / `merged_v7` | `names=[streetlight_on, streetlight_off, streetlight_damaged]`（`streetlight_occluded` `d1` 原始 `235` 框（`merged_v5` 保留 `227` 框，`8` 去重损失）`~95%` 错标 `~22%` 自证救回后弃用——`D-41`） |
| `merged_v6`/`merged_v7` | `merged_v5` → `mean_v>100` 全 `on` 删帧 `3,088` + `occluded` 自证 `conf>=0.65`/`IoU>=0.1` `39` 改判 `on`/`188` 删 + `damaged` 全保 `1,423` → `merged_v6`（`nc=4`）→ `--drop-occluded` `merged_v7`（`nc=3`） |
| `D-30`/`D-30` 参照框 | 夜间正常亮灯 `streetlight_on` 置 `is_fault_candidate=false` 回传前端作参照（`visual_signal_state="NORMAL_LIT"`） |
| `whitelist` | `src/backend/tomori/vision/whitelist.py` 上传校验链（魔数→多帧→像素防炸弹→EXIF→解码） |
| `mapping` | `src/backend/tomori/vision/mapping.py` `raw_class` → `candidate_fault_type`/`visual_signal_state`/`is_fault_candidate`/`suggested_severity_hint` 映射层 |
| `e2e`/`one2one`/`one2many` | YOLO26 `end2end=True` 端到端头（`nms=False` 输出 `[1,300,6]`）为**权威头**，`one2many`+外接 NMS 为对照头；「早停判据头 == 部署头」经 `nms=False` 全链路锁定 |
| `data.yaml.names` 权威源 | `trainer.py` 以 `data.yaml.names` 前缀子集校验 `RAW_CLASSES` 词汇母集（`D-43`），同一 `trainer.py` 兼容 `nc=3`/`nc=4` |
