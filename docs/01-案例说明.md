# 01-案例说明（`#141` 公共照明故障工单系统）

> **适用读者**：全员。

---

## 1. 背景与目标

郑州市城市照明日常巡查以「**灭灯 / 灯具破损 / 灯头遮挡**」三类高频故障为主：巡查员现场拍照上报 → 运维管理员分级派工 → 维修员接单维修 → 巡查员验收闭环。流程法定 `48h` 时限刚性（郑州令第 `152` 号第 `19` 条第 `3` 款，`D-11`）、责任链需全程可审计。`#141` 系统构建**工单全生命周期管理 + 静态图片 AI 辅助识别**的单体应用（`FastAPI` + `Vue3` + `PostgreSQL 17`，视觉推理为进程内 Python 模块，`D-37`）。

**闭环**：`报障 → 分级派工 → 维修 → 验收 → 关闭或返修`（`max_rework_rounds = 2` 上限）。
**AI 辅助不替代**：`yolo26s` `nc=3`（`merged_v8`/`streetlight_v5` 当前部署，`--clean-damaged-lamp-model` `d3` `damaged` 灯头过滤 `176` 框剔/`1,247` 框保）输出 `streetlight_on`/`streetlight_off`/`streetlight_damaged` 候选，**AI 产出必须经巡查员确认**方可建单（`requires_inspector_confirmation` 恒 `true`，`V1`）；夜间正常亮灯按 `D-30` 以 `is_fault_candidate=false` 回传参照（`visual_signal_state="NORMAL_LIT"`）；`streetlight_occluded` 已按 `D-41` 弃用（`d1` 源 `235` 框/`merged_v5` 合并 `227` 框 `~95%` 错标 `~22%` 自证救回，`API` `fault_type=OCCLUDED` 保留手工报障）。

### 2.1 核心业务流程

```text
INSPECTOR 上传 1..10 静态图
  → whitelist 四层校验（魔数→多帧/视频→40MP→EXIF→解码）
  → VisionClient.analyze()（nc=3 onnx + OpenCV 融合 → mapping 业务枚举）
  → 无 is_fault_candidate=true → 200 {ticket: null, evidences: [...]}（留证不建票，D-30/FR-15）
  → 否则建票 AI_CANDIDATE_PENDING + fault_evidences + audit_logs + Idempotency-Key
  → INSPECTOR 逐条 confirm → grading_rules 分级快照 + repair_deadline_at +48h → PENDING_DISPATCH
  → ADMIN dispatch（确认+授权+在途<3+同票无活跃派工）→ DISPATCHED
  → TECHNICIAN accept/reject → IN_REPAIR → complete（电气安全检查 5 项全 true + safety_note）
  → PENDING_ACCEPTANCE → INSPECTOR APPROVED→CLOSED / REJECTED→REWORK_PENDING_DISPATCH（round≤2）/MANUAL_REVIEW（>2）
  → MANUAL_REVIEW → APPROVE_REASSIGN/SPECIAL_CLOSE/TERMINATE_CANCEL 出口
```

### 2.2 非业务范围（`N1`–`N5` 硬红线，不可扩展）

| 红线 | 内容 | 拒绝方式 |
