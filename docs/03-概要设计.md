# 03-概要设计

> **适用读者**：架构、新成员、前后端实现者。
> **事实基线**：`src/`（`src/backend/tomori` 单包 + `src/frontend` + `src/database`）、`migrations/versions/0001..0004`、`tests/`、`vision/{weights,reports}`（gitignored 产物）。

## 1. 系统架构

单体 **FastAPI + Vue 3 SPA + PostgreSQL 17** 应用；AI 视觉推理为**进程内 Python 模块**（`D-37`，不做独立视觉服务），通过 `src/backend/tomori/vision/` 的函数内延迟导入（`ultralytics`/`onnxruntime`/`cv2`）实现 `uv sync`（主包）与 `uv sync --extra vision`（视觉）双轨。

```text
┌─────────────────────────────────────────────────────────────────────┐
│  客户端 — Vue 3 SPA（src/frontend/：views / components / stores / api） │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ HTTP/JSON（JWT Bearer + X-Idempotent-Key）
┌───────────────────────────────▼─────────────────────────────────────┐
│  FastAPI Backend（src/backend/tomori/）                                │
│  api/（薄壳：deps/errors/v1 路由） → services/（重逻辑：状态机/事务）     │
│  models/（SQLAlchemy 17 表） → schemas/（Pydantic 契约）                │
│  workers/（notifier + sla_scanner） → vision/（whitelist→client→        │
│    mapping→metrics，进程内 ONNX+OpenCV 融合）                            │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ SQLAlchemy Async + psycopg v3
        ┌───────────────────────┴───────────────────────┐
        │ PostgreSQL 17.12（src/database/schema.sql 直建） │
        │ 17 表 / 76 CHECK / 41 FK / 37 索引 / 6 部分唯一   │
        │ migrations/versions/0001..0004（Alembic）        │
        └───────────────────────────────────────────────┘

远端训练链（RTX 4080 SUPER，`/root/autodl-tmp/tomori/`）：
  rsync src → dataset_prep（merged_v6 → merged_v7 nc=3 清洗）
  → trainer.py（yolo train batch=24/imgsz=1280）→ export ONNX
  → metrics.json + SHA256SUMS → rsync 回传 → client.py D-30/damaged 验收
```

### `web/` → `src/frontend`（阶段二布局变更注记）

早期文档中的 `web/` 前端目录已并入 **`src/frontend/`**（同一份 Vue 3 SPA）；`alembic.ini`/`migrations/` 仍在**仓库根**（`Lead` 裁决）。运行时产物 `vision/{weights,reports,datasets,runs}`（gitignored）仍在根级 `vision/` 与 `src/backend/tomori/vision/` 源码分离。

## 3. 模块划分与职责依赖（红线）

| 层 | 模块 | 职责 | 不可为 |
|---|---|---|---|
| **API（薄壳）** | `api/deps.py`/`errors.py`/`idempotency.py`/`v1/*.py` | HTTP→service 调用、Pydantic 参数、幂等键与 `error.code` 契约 | 不 `import fastapi.Request/Response` 之外的 DB 会话；不写 `audit_logs` |
| **服务（重逻辑）** | `services/{state_machine,ticket_service,dispatch,rework,sla,grading,auth,media,exceptions}.py` | 状态机唯一入口、单事务不变量、SLA 扫描、确定性分级、幂等、媒体流 | 不经 `transition_*` 改 `status`；不跨事务提交 |
| **模型** | `models/*.py`（`17` 表 SQLAlchemy 定义，`76` CHECK/`41` FK/`37` 索引/`6` 部分唯一） | 表结构与约束 | 不写业务逻辑 |
| **Schema** | `schemas/*.py`（`6` 文件） | Pydantic 出参/错误契约 `response_model` | 不返 ORM 实体直出 |
| **Worker** | `workers/{notifier,sla_scanner}.py` | 通知投递（`process_due_notifications_once`）+ `sla_scan` 定时 | 不写 `status` 直改——全部经 `transition_*` |
| **视觉** | `vision/{whitelist,client,mapping,metrics,contract,errors,image_io,baseline,config,eda,dataset_prep,trainer}.py`（`13` 文件） | 图片四层白名单 → `VisionClient`/`client.py` 推理 → `mapping` 业务枚举 → `metrics` 融合 + `D-30`/`D-31` 契约 | 不产出 `FLICKERING`/`ELECTRIC_HAZARD`（`V3`）；不做独立服务 |
| **DB** | `db/{base,session,types}.py` | `DeclarativeBase` + Async session + `ARRAY`/`JSONB` 类型 | 不裸 `psycopg` 直查 |
| **前端** | `src/frontend/src/{views,components,stores,api,router}.ts/.vue` | SPA 三角色视图、`128` `data-testid` 冻结锚点、`fallback banner` `MANUAL_REPORT` | 不绕过 `data-code`/`data-fallback-action` 错误提示 |
| **测试** | `tests/{unit,integration,e2e}` | `118` 单测/集成 + `31` E2E 全绿 | 不使用 `mock`/`patch` 替代真实链 |
| **配置** | `config/application.example.yml`、`.env.example` | `__PLACEHOLDER__` 模板 + `Settings` 字段映射 | 真实值不入库（`.env`/真实 `application.yml` `gitignored`） |

### 依赖红线

- `api` 仅可 `import services/schemas/db`；`services` 可 `import models/db/vision`；`models` 仅表定义；`workers` 仅消费 `services/state_machine`；`vision` 进程内函数内延迟导入 `ultralytics`/`onnxruntime`/`cv2`；
- **唯一状态变更入口**：`fault_tickets`/`dispatch_records`/`rework_orders`/`notification_tasks` `status` 更新**只允许**经 `src/backend/tomori/services/state_machine.py` `transition_*()`（`I7`/`I8`）；
- **不变量**：`I1` 同点位同类活跃单一票（`uq_fault_tickets_active_point_type`）/`I4` `ELECTRICAL_SAFETY_CHECK_REQUIRED` 完工前置/`I7` 审计/`I8` 通知 fan-out；
- **`web/` → `src/frontend`**、`src/tomori/` → `src/backend/tomori/` 两层 `src` 布局（`pyproject.toml` `module-name="tomori"`/`module-root="src/backend"`）。
